# Attribute Families and Counteracting Molecules

This document records the current attribute framework and a proposed naming set for the fictional molecules that counteract each attribute.

> **Important:** The player is not given a solution reference table. The pairings below are design data for the developer. In the game, Elara must discover the relationships through research and experimentation.

All names below are working proposals. The user has selected the direction of having four families and undisclosed solutions, but has not explicitly locked these particular names.

## Core rules

- There are exactly four attribute families.
- Families I, II, and III each contain three attributes.
- Family IV contains five possible attributes.
- Attributes are binary: present or absent. They have no numerical values.
- Every attribute has a corresponding counteracting fictional molecule.
- A disease/immune-cell profile determines the molecule set needed for a cure.
- The cure must be an **exact match**: no missing molecules and no extra molecules.
- Order does not matter. Duplicate molecule entries should be removed.
- The player discovers attribute-to-molecule relationships experimentally. No solutions are displayed in a player-facing reference table.
- Family IV is intended to be especially difficult to research.

### Final-family research intent

Family IV should feel fundamentally more difficult to understand than the earlier families. The player should not receive its counteracting molecules as a reward for simply scanning the final case. The intended challenge is to infer the correct relationship through experimentation and accumulated research knowledge.

Do not make the final family a brute-force wall. The eventual research design should provide enough interpretable feedback for a careful player to make progress without requiring an unreasonable number of blind trials.

## How profiles produce cures

The game's data model should keep the two concepts separate:

1. The case stores a set of **attribute IDs**.
2. Research knowledge stores the discovered mapping from each attribute ID to its counteracting **molecule ID**.
3. The required cure is generated by looking up the counteracting molecule for every attribute in the case profile.
4. The Bioassay Simulator compares the submitted molecule set with the required molecule set.

No separate hand-authored cure recipe is needed for every case.

## Example — abstract logic

If a case has attributes `{F1_A, F2_C}`, and the player has discovered their counteragents, its required cure is the corresponding molecule set `{M_VEY, M_KYN}`.

The player-facing game should not display this mapping automatically. This example is for implementation clarity only.
